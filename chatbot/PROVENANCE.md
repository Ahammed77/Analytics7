# Demo dataset provenance

**No row is live customer data.** Every row in the reporting database is synthetic. It was written for the Analytics 7 chatbot demo (FR-11, story 46).

| What | Where | How it was made |
|---|---|---|
| Table shapes | `db/schema.sql` | Copied from the CIS tables that the in-scope Cube YAMLs read (`cube/model/cubes/*.yml`). Only the columns those cubes use are kept. One extra column, `pu_account.cust_class`, is an assumption for the customer-class overlay. |
| Rows | `db/seed.sql` | Generated by `db/make_seed.py` from hand-written planted rows plus filler from fixed word lists and a fixed random seed (`20261208`). Re-running it gives the same file. |
| Read-only role | `db/roles.sql` | `a7_reader`, with SELECT on the tables and read-only transactions by default. |

## What is in it

- **Planted accounts** 100101 to 100107. Names are invented, and the cities "Port Alder" and "Cedar Falls" are made up. These accounts sit behind the approved questions in `config/approved_questions.yml`. Their balances, cash receipts and calls are set by hand so every expected answer is known in advance (story 47).
- **Filler accounts** 100201 to 100240. Names are combinations from two fixed word lists. Balances are random but capped below the planted thresholds (overdue at most $60, total at most $240), so filler never changes an approved answer.
- **Closed billing periods**: rows with `end_date` set for 100105, 100201 and 100202. Each carries a $999 overdue amount. They show that the Account Balance cube's `end_date IS NULL` filter works.
- **Cash batches** on 12, 14 and 15 September 2026 (cashiers `jlee`, `mokafor` and `srao`).
- **Cash receipts** on 8 and 9 January 2026. Some rows are deliberately excluded by the Cash Detail cube's filters: a non-CR journal and a GL-application journal.
- **CSR calls**: 12 calls in 2025 with fixed counts per call type and per agent, plus 3 calls outside 2025 to test date boundaries.

No anonymised extract of real CIS data was used. If the demo later switches to anonymised data (Q8), update this file and the approved expected results together.

## Regenerating

```bash
python db/make_seed.py
```

The approved-question expected results must be updated by hand whenever the planted rows change.
